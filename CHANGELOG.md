# Changelog

All notable changes to `diffdash` are tracked here.

## Unreleased

- Mouse support. A click on a tab switches to it, on a row of a list selects it, on a range pill in Stats picks that range, and on a day of the heatmap selects that day in By day (a day with no commits in the range has no row there, so nothing happens). Section headers and rows of graph lines cannot be selected, as with the keys. A double click on a row opens it in less, like Enter; a single click never does, since less takes over the screen. The wheel moves the selection like `j` and `k`. It has to: with mouse reports on, the terminal sends the wheel to diffdash instead of turning it into arrow keys, which is how the wheel moved the selection before in terminals like Ghostty. diffdash asks only for presses, releases and the wheel, because reports of pointer motion would cost a redraw for every cell the pointer crosses. A double click opens on the release of its second press, not on the press: a release reported once less had started would reach less as keys. Mouse reports are off while less runs, so its wheel works as before, and when diffdash exits, also after a panic, so the shell never prints clicks. While diffdash runs, selecting text in the terminal needs a modifier held as you drag, Shift in Ghostty.

## 0.3.1 - 2026-11-06

- Fix: the Stats heatmap drew tall rectangles and filled only part of the row. Below 113 columns a day was one cell wide, and a terminal cell is about twice as high as it is wide, while the year took 58 of the 106 cells in a 108-column window. Wider windows stopped at 111 cells. A day is now always two cells wide, which makes about a square. A window under 114 columns shows fewer weeks instead, without the oldest (50 weeks at 108 columns, 26 at 60), and the title says how many. A wider window puts the extra columns between the months, so the map reaches the edge at any width. The weeks of a month keep touching, because with gaps between columns and none between rows, a stack of equal days reads as one tall bar. The key on the bottom border uses the same squares. `--once` is unchanged: it does not fit its output to a width, and a year of squares would wrap in any terminal under 112 columns.

## 0.3.0 - 2026-11-05

- The Stats tab now has a GitHub-style heatmap above its tables: one cell per day for the last 53 weeks, shaded by lines added plus deleted. By day has the same numbers, but as a list limited to the range, so a year's rhythm could not be seen at a glance. The map ignores `t`, and otherwise counts what the rest of Stats counts: commits on HEAD, without merges, by commit date. The shade is in the glyph (`░ ▒ ▓ █`, and `·` for a day with no commits), because the UI uses only the terminal's palette colors, so it follows light and dark themes. Each shade holds a quarter of the days with commits, so one huge commit does not leave the other days looking empty. The day selected in By day is marked on the map. It takes 10 rows, so the tables get shorter, and a terminal under 29 rows leaves it out and looks as before. A day is two cells wide from 113 columns and one below that; below 60 columns the oldest weeks go. `--once` prints the map too. It reloads when HEAD moves, on a background job that reads a year of `git log --numstat`: about 1 s on a repo with 940 commits that year.

## 0.2.2 - 2026-11-04

- Fix: file names could not be read in a narrow pane, such as a split screen. The file lists (Changes and the lower panes of Log and Branches) kept 41 cells for the numbers and the bar at any width, and a long path was clipped on the right, so at 60 columns a row showed `crates/diffd` and never reached the file. The lists now make room in this order: the padding of the number columns, the bar, then the path. A path that still does not fit loses whole directories from the left (`…/auth/login.rs`), and a rename shows only its new path after an arrow (`→ …/auth/login.rs`). A pane where every path already fit looks the same as before. Enter and `--once` still show full paths.
- Fix: in a narrow pane, the Log tab's commit list lost the subject first. The author, date and number columns had fixed widths and the commit column got what was left, so at 60 columns a row read `* f512 t` and at 40 columns the hash and subject were gone. The list now gives up the padding, then the author, the date and the hash, in that order, to keep 24 cells of subject; the pane below still shows all three for the selected commit. Columns are hidden whole instead of being clipped to `8 minut`. A pane with room for that much subject looks the same as before.
- Fix: in a narrow pane, the Branches tab's list hid the branch names; at 60 columns none were left. The fixed columns took all the room and the name column got the rest, despite the rule that names win over the bar. The list now gives up the padding, then the bar, then the words in `1 ahead 0 behind` (now `↑1 ↓0`), then the date. A name that still does not fit loses its tags, then its start (`…/feature`), like a file path. Below about 40 columns the ahead, behind and file counts go too, so that a name stays readable; `+` and `-` always stay. A pane where names and a whole bar fit looks the same as before.
- Fix: in a narrow pane, the Stats tab cut off what each row was about. Its columns had fixed widths, so at 60 columns every day read `2026`, and directories and authors read `(roo` and `陈志`. Each table now measures what it holds and gives up the padding of its number columns, then its bar, then the commit count; `+` and `-` are never cut. A day that still does not fit shows `11-01`, and a name is cut on the right (`Christop…`). Tables also look different at 80 columns and up to 100: less padding and longer bars. A table looks as before once a bar of 4 cells fits beside its padding, which is from 86 columns for By day and from 100 for the other two. An author or directory longer than 17 cells is no longer cut at any width: it takes up to 40 cells from the bar. The box on top now gives up the words `· range`, the note and the net count one at a time and whole, so at 40 columns the range pills still show and no total is cut in half.
- Fix: in a narrow pane, the tab bar lost its tabs. They came last on the line, so at 60 columns tab 4 did not show, and while on it no active pill could be seen; a long branch name hid even more. All four tabs now fit down to 23 columns. The bar gives up the `diffdash` badge, then the tab names, which leaves their numbers (the panel below names the current tab), then the start of the branch name and the end of the repo name. A bar where everything fits looks the same as before.
- Fix: in a narrow pane, a message that stands in for a list lost its end. Below 86 columns the note on a merge commit was cut, and at 40 columns it stopped at `no per-`. The same went for the text on the current branch and for the error of a branch or a failed tab, where the reason comes last. These messages now wrap. A message that fits looks the same as before.
- Fix: in a narrow pane, a panel title could end in the middle of a number, because a title was simply cut at the border. At 50 columns the title over a commit's files lost its `-0`, and `+66` could have read as `+6`. Titles with counts now give up whole pieces instead: the Changes title loses `since HEAD`, then the file count; the title over a commit's files loses its counts, then shortens the author to keep the date; the title over a branch's files loses the merge base, then files and lines, then ahead and behind. The Branches title shows `compared with main` whole or not at all, instead of `compared with ma`. A worktree path loses its start, so it still ends in the worktree's name. A title that fits looks the same as before.
- Fix: in a narrow pane, `loading…` and errors could not be seen. They came after the key hints, which filled the bar at 60 columns on the Log and Branches tabs, so a repo going bad while diffdash ran showed nothing at all. The bar now gives up hints, whole and from the end, to show them first, which also ends hints cut to `· q q`. Errors now start with git's own words: `fatal: bad object HEAD (git diff --cached --numstat -z HEAD)` instead of `git diff --cached --numstat -z HEAD failed: fatal: bad object HEAD`, because the arguments could fill the room before the reason, even at 90 columns. `--once` prints this wording too. A bar where everything fits looks the same as before.

## 0.2.1 - 2026-11-03

- The tab bar at the top and the key hints at the bottom now sit in rounded boxes of their own, like the panels between them. They used to be bare lines of text above and below the boxed panels; now the whole screen has one look. Each bar takes three rows instead of one, so the panels get four fewer rows.

## 0.2.0 - 2026-11-03

- New **Branches** tab (key `4`). Log and Stats only follow HEAD, so work on another branch, such as an agent's branch in its own worktree, did not show up until it was merged. The tab lists every local branch with commits ahead of and behind the current branch, and the files and `+/-` lines it changed since its merge base with HEAD (the range a pull request shows). The lower pane lists the selected branch's files; Enter opens the whole branch diff in less. The tab refreshes by itself when any branch tip moves. Comparisons are cached by HEAD and tip commit, so only branches that moved are recomputed. A branch with no common history shows that on its own row instead of failing the tab. `--once` prints a Branches section too.
- Fix: the 2 s poll could still rewrite `.git/index`, and so take `.git/index.lock`, whenever a tracked file had a new mtime but unchanged content (for example after an agent or formatter rewrote it as-is). An agent's `git commit` at that moment could fail. `--no-optional-locks` does not stop `git diff` from refreshing the index, so every git call now also passes `-c diff.autoRefreshIndex=false`. The git call behind Enter (the pager) used neither setting and now uses both.

## 0.1.0 - 2026-11-02

- Initial version: a read-only TUI with three tabs that show line counts. **Changes** lists staged, unstaged and untracked files with `+/-` counts, bars and totals, refreshing every 2 s. **Log** shows the commit graph with per-commit `+/-` and a pane listing each commit's files. **Stats** gives 7d/30d/90d/all totals by day, top-level directory and author.
- Untracked files are counted line by line (`git diff --stat` leaves them out), with a per-file cache keyed on mtime and size so large untracked files are not re-read on every poll.
- Every git call uses `--no-optional-locks`, so polling never takes `.git/index.lock` and cannot break a concurrent `git commit` by an agent or the user.
- The Changes title shows totals since HEAD (`git diff HEAD` plus untracked files), so a file that is both staged and unstaged is counted once.
- Diffs open in `less -R -+F`, so a user's `LESS=-F` cannot close a short diff before it can be read.
- The UI uses only ANSI palette colors and reverse-video selection, so it stays readable in both light and dark themes. All panels have rounded corners. The active tab, the diffdash badge and the selected Stats range are rounded pills with Powerline half-circle caps.
- `--once` prints all three views as plain text for scripts and quick checks.
